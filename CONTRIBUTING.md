# Как добавить игру или улучшить профиль

Профили лежат в `games/*.json` и встраиваются в программу при сборке. Чтобы проверить профиль без пересборки, положите файл в `%APPDATA%\FahrenHack\games\`: он заменит встроенный профиль с тем же `id`.

## Правила для профилей

1. **Только одиночные игры и режимы.** Не принимаются профили для онлайн-режимов, игр с античитом, рейтингов и соревнований.
2. **Без платного контента.** Никаких читов на DLC, микротранзакции, внутриигровую валюту за реальные деньги и разблокировку лицензий.
3. **Без обхода защиты.** Патчи (`patch`) не должны отключать DRM, anti-tamper, проверки целостности или античит. Файлы игры на диске не изменяются никогда.
4. **Только свои находки.** Не копируйте таблицы Cheat Engine, скрипты и офсеты из чужих трейнеров и форумов. Значения ищите сканером FahrenHack. Если находка чужая, получите разрешение автора и укажите его.
5. **Без ассетов игры.** Никаких логотипов, обложек, скриншотов и текстов из игры. Описания читов пишите своими словами.

## Формат профиля

```json
{
  "id": "mygame",
  "title": "Название игры",
  "subtitle": "Год или издание",
  "processes": ["game.exe"],
  "steam_appid": 123456,
  "accent": "#2b4c6f",
  "notes": "Подсказка, которую видит игрок",
  "pointer_scan": { "max_depth": 5, "max_offset": 4096 },
  "cheats": [
    {
      "id": "money",
      "category": "Ресурсы",
      "icon": "coin",
      "name": "Деньги",
      "description": "Что делает чит",
      "kind": "set",
      "vtype": "i32",
      "value": "999999",
      "hotkey": "F3",
      "locator": { "type": "calibrate", "mode": "exact", "prompt": "Сколько у вас денег?", "steps": ["Шаг 1", "Шаг 2"] }
    }
  ],
  "builds": {}
}
```

### Категории

Необязательный раздел `categories` задаёт порядок и иконки категорий:

```json
"categories": [ { "name": "Игрок", "icon": "user" }, { "name": "Оружие", "icon": "gun" } ]
```

Категории, которых нет в списке, идут следом в порядке появления.

### Поля чита

- `kind` — вид элемента управления:

  | `kind` | В интерфейсе | Что делает |
  |---|---|---|
  | `freeze` | переключатель | держит значение или патч кода, пока включён |
  | `set` | кнопка «Применить» | записывает `value` один раз |
  | `number` | «−», поле, «+» | показывает значение из игры, меняет его на `step`, пишет введённое; `min` и `max` ограничивают |
  | `slider` | ползунок | настройка от `min` до `max` с шагом `step`; `off_value` выключает чит. Для множителей, урона, скорости |
  | `select` | список и «Применить» | записывает выбранный из `options` вариант (`{ "label": "…", "value": "…" }`) |

- `vtype`: `i32`, `i64`, `f32` или `f64`.
- `value`: значение по умолчанию. Для `freeze` значение `null` означает «держать то, что было в момент включения». Для `slider` и `select` — начальная позиция.
- `hotkey`: клавиша вроде `F1`, `CTRL+F2`, `SHIFT+NUM5`, `ALT+K`. Для `number` и `slider` это «больше», для `select` — следующий вариант.
- `hotkey_down`: «меньше» или предыдущий вариант. Только для `number`, `slider` и `select`.
- `info`: подсказка за значком «i». `warn`: предупреждение за жёлтым значком «!» — побочные эффекты, о которых игрок должен знать.
- `icon`: `heart`, `ammo`, `coin`, `gem`, `knife`, `star`, `bolt`, `user`, `bag`, `chart`, `gun`, `skull`, `flag`, `run`, `flame`, `timer`, `key`, `shield`, `target`, `eye`.

### Способы найти значение (`locator`)

| `type` | Что это |
|---|---|
| `calibrate` | Мастер находит значение на ПК игрока: `mode: exact` для видимого числа, `unknown` для полоски. Затем FahrenHack строит цепочки указателей. |
| `pointer` | Фиксированная цепочка: `{ "module": "game.exe", "offsets": ["0x1234", "0x10", "0x8"] }`, то есть `[[game.exe+0x1234]+0x10]+0x8`. |
| `aob` | Байтовая сигнатура в модуле. Необязательный `rip: [смещение_disp32, длина_инструкции]` для RIP-адресации, затем `offsets` как у `pointer`. |
| `patch` | Замена байтов по сигнатуре: `pattern`, `offset`, `bytes`. При выключении исходные байты восстанавливаются. |
| `inject` | Инъекция кода: `size` байт (минимум 5) по сигнатуре (`pattern` + `offset`) заменяются переходом в код-пещеру рядом с модулем. Там выполняется `code`. При выключении исходные байты восстанавливаются. |

### Шаблон `code` для `inject`

Байты в hex через пробел и подстановки:

| Подстановка | Что вставляется |
|---|---|
| `{orig}` | исходные байты, которые затёрты переходом. Нельзя использовать, если среди них есть адресация относительно RIP |
| `{return}` | переход обратно, на первую инструкцию после затёртых байтов (5 байт) |
| `{param}` | rel32 до ячейки параметра, для инструкции, у которой смещение — последнее поле. Пример: `F3 0F 59 05 {param}` = `mulss xmm0, [param]` |
| `{param_abs}` | 8-байтовый абсолютный адрес параметра. Пример: `48 B8 {param_abs}` = `mov rax, param` |

Параметр — это значение ползунка (`slider`), выбранный вариант (`select`) или `value` переключателя, записанное как `vtype`. Ползунок меняет его на лету, не трогая код. Два чита не могут одновременно патчить один и тот же код: второй получит понятную ошибку.

Пример из `tools/e2e.ps1` — «урон за удар» для тестовой игры, где `take_damage` скомпилирована в `lock sub [rcx+18h], edx; ret`:

```json
{ "id": "dmg", "kind": "slider", "vtype": "i32", "min": 0, "max": 50, "step": 1, "off_value": "7",
  "locator": { "type": "inject", "pattern": "F0 29 51 18 C3 CC", "size": 5,
               "code": "8B 15 {param} F0 29 51 18 C3" } }
```

Здесь `mov edx, [param]` подменяет урон, а затем идут исходные `lock sub` и `ret`.

### Проверенные цепочки (`builds`)

После настройки чита FahrenHack сохраняет цепочки в `%APPDATA%\FahrenHack\calibration\<game>\<build>.json`. Сборка игры определяется по заголовку её exe и выглядит так: `5f3a2b1c-1a2b000`.

Цепочку можно добавить в профиль, если она **подтверждена минимум в двух запусках игры**: `confirmations` ≥ 2, и после перезапуска чит находил верное значение. Пример:

```json
"builds": {
  "5f3a2b1c-1a2b000": {
    "money": [ { "module": "game.exe", "offsets": ["0x2F1A8C0", "0x18", "0x2C4"] } ]
  }
}
```

С таким разделом чит на этой сборке работает сразу, без настройки.

## Перед pull request

```bash
cargo test
```

Тест `builtin_profiles_parse` проверяет, что встроенные профили читаются: в них уникальные `id`, корректные клавиши, значения, варианты `select`, пределы `slider`, сигнатуры и шаблоны `inject`.

Изменения движка проверяйте ещё и сквозным тестом: `powershell -ExecutionPolicy Bypass -File tools\e2e.ps1`.
