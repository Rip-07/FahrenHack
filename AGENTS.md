# AGENTS.md — FahrenHack

Инструкции для ИИ-агентов (Codex и др.). Владелец проекта пишет по-русски: **отвечай по-русски**. Тексты интерфейса тоже на русском. Код, идентификаторы и комментарии — на английском.

## Что это

FahrenHack — открытый (MIT) трейнер для **одиночных** игр на Windows:

- интерфейс в стиле игровой консоли в окне WebView2, с навигацией с клавиатуры и геймпада;
- готовые профили игр (первый — Resident Evil 4 2023, `games/re4r.json`);
- мастер калибровки, который один раз находит значение и строит к нему цепочки указателей;
- сканер памяти в духе Cheat Engine;
- пульт на телефоне по Wi-Fi (тот же интерфейс в браузере).

Состояние, что проверено и что осталось сделать — в [docs/STATUS.md](docs/STATUS.md). Правовые рамки — в [LEGAL.md](LEGAL.md), правила для профилей — в [CONTRIBUTING.md](CONTRIBUTING.md).

## Команды

Только Windows 10/11 x64. Нужны Rust (MSVC), Windows SDK и WebView2. В Linux-контейнере проект не собирается и не тестируется.

| Команда | Что делает |
|---|---|
| `cargo build` | debug-сборка: `target\debug\fahrenhack.exe`, с консолью и devtools |
| `cargo build --release` | `target\release\fahrenhack.exe`, без консоли |
| `cargo test` | юнит-тесты: hex, сигнатуры, клавиши, сканер, сборка кода инъекции, разбор встроенных профилей, защита `app.js` от конфликта с `window.ipc` |
| `powershell -ExecutionPolicy Bypass -File tools\e2e.ps1` | сквозной тест движка на `tools/dummy-game` через HTTP API: калибровка, поиск указателей, заморозка, перезапуск игры. Ожидается `ALL CHECKS PASSED` |
| `powershell -ExecutionPolicy Bypass -File tools\window-check.ps1 [-Drag]` | проверка **настоящего окна** через CDP WebView2: интерфейс загрузился, кнопки окна работают, `-Drag` двигает окно реальной мышью. Скриншот кладёт в `%TEMP%\fahrenhack-window.png` |
| `cargo build --release --manifest-path tools\re-probe\Cargo.toml --target-dir target\re-probe` | инструмент для профилей: `watch` (кто пишет или читает адрес, через аппаратные точки останова), `dis`, `read`, `find`/`snap`/`filt` (поиск значения), `ptr`/`xref` (кто хранит указатель, какой код грузит статическую переменную), `aob` (сколько раз встречается сигнатура), `tdbobj`/`tdbinst`/`tdbfield`/`tdbimpl`/`tdbgrep`/`tdbmethods`/`tdbregall`/`ftable`/`fuses`/`listitems` (база типов RE Engine: поля и методы по имени, таблицы функций классов). Ничего не патчит |
| `fahrenhack --browser` / `--headless` | интерфейс в обычном браузере / только сервер |

Перед `cargo build` закрой запущенный `fahrenhack.exe`, иначе линкер не перезапишет файл: `Get-Process fahrenhack | Stop-Process -Force`.

После правок в `src/ui/*` нужна пересборка: интерфейс встроен в exe через `include_str!`.

Тесты и ручные запуски делай с `FAHRENHACK_DATA=<временная папка>`, чтобы не трогать настоящие данные пользователя в `%APPDATA%\FahrenHack`. Скрипты в `tools/` делают это сами.

## Проверка изменений

- **Движок** (`mem`, `scan`, `pointer`, `app`, `web`): `cargo test` + `tools\e2e.ps1`.
- **Интерфейс**: проверяй в настоящем окне через `tools\window-check.ps1`, а не только в браузере. Однажды интерфейс работал в браузере и был пустым в окне.
- **Вёрстка для телефона**: открой `fahrenhack --browser` и сузь окно до 375 px.
- Не включай пульт в автотестах: Windows покажет пользователю запрос брандмауэра.

## Устройство

| Путь | Что внутри |
|---|---|
| `src/main.rs` | запуск: сервер в отдельном потоке → окно (или `--browser` / `--headless`) |
| `src/window.rs` | окно tao + wry без рамки; IPC `drag`, `min`, `max`, `fullscreen`, `close` через `EventLoopProxy` |
| `src/web/` | сервер axum, защищённые маршруты `/api` и раздача встроенного интерфейса. Токен передаётся в `x-token` или `?t=`. Сервер слушает `127.0.0.1` и поднимает адрес LAN при включённом пульте. Запросы не с loopback при выключенном пульте получают 403 |
| `src/app/` | подключённая игра, читы, калибровка, настройки, состояние для API и блок античитов. Задачи `Job` опрашиваются через `/api/job`. Фоновые потоки выполняют заморозку каждые 40 мс, проверяют клавиши каждые 30 мс и ищут игру для автоподключения раз в 2 с |
| `src/mem.rs` | WinAPI: процессы, модули, регионы памяти, стеки потоков (TEB), отпечаток сборки (PE timestamp + размер образа) |
| `src/scan.rs` | точный поиск, снимок памяти на диск (`%TEMP%\fahrenhack-*.snap`), отсев |
| `src/pointer.rs` | цепочки `[[module+o0]+o1]+…`, поиск указателей (обратный BFS по отсортированной карте указателей) |
| `src/profile.rs` | формат профилей (локаторы `pointer`, `aob`, `patch`, `inject`, `item` — предмет в списке инвентаря по номеру, `calibrate`), встроенные профили (`games/*.json` через `include_str!`), калибровки, свои читы, `read_json` с поддержкой BOM |
| `src/inject.rs` | инъекция кода: шаблон `code` с подстановками `{orig}`, `{return}`, `{param}`, `{param_abs}`, `{addr:ID}` (адрес значения другого чита, обновляется приложением), сборка кода-пещеры и перехода. Память под пещеру выделяет `Process::alloc_near` |
| `src/aob.rs`, `src/hotkey.rs`, `src/steam.rs`, `src/logo.rs` | сигнатуры; горячие клавиши (`GetAsyncKeyState`); Steam: реестр, библиотеки, локальные обложки, запуск; логотип для иконки (используется и в `build.rs`) |
| `src/ui/` | одна страница для окна и телефона. `app.js` управляет экранами и событиями, `api.js` выполняет запросы, `cheat-list.js` обновляет список читов, `view-helpers.js` содержит общие функции отображения |

Данные пользователя (`%APPDATA%\FahrenHack`): `settings.json`, `calibration/<game>/<build>.json`, `custom/<game>.json`, `games/*.json` (переопределяют встроенные), `webview/` (профиль WebView2).

## Подводные камни (на каждый уже наступали)

1. **`window.ipc` в окне.** wry объявляет `window.ipc` неизменяемым свойством. Поэтому:
   - `app.js` грузится как модуль (`<script type="module">`);
   - нельзя объявлять глобальное `ipc`: иначе SyntaxError и пустое окно;
   - для вызова окна используй функцию `host(msg)`;
   - модуль не создаёт глобальных имён, поэтому в HTML-атрибутах нельзя вызывать функции из `app.js`: используй делегирование через `data-act` и таблицу `ACTIONS`.
2. **Не пересоздавай кликабельные элементы при опросе.** Состояние опрашивается каждые 800 мс. Строки читов обновляются по частям (`renderCheatList` + `patchHtml`): если пересоздать кнопку между нажатием и отпусканием мыши, клик теряется.
3. **Модальные окна.** `drawModal()` меняет только содержимое `.mcard`, сама карточка остаётся, иначе анимация появления мигает при каждом шаге.
4. **Мобильная вёрстка.** У `#top` не должно быть `backdrop-filter` (а также `transform` и `filter`): он делает шапку контейнером для `position: fixed`, и нижняя панель вкладок прилипает к шапке.
5. **Стеки потоков.** `Process::regions()` исключает стеки потоков: там лежат временные копии значений, которые давали ложных кандидатов и ломали привязку.
6. **Выбор цепочки.** `pick_chain` берёт первую цепочку, которая ведёт в читаемую память. Цепочки хранятся от лучшей к худшей. Голосование не использовать: много длинных цепочек сходятся на неверном адресе.
7. **Калибровка привязана к сборке игры** (`build_key`). Повторная настройка в новом запуске оставляет только подтверждённые цепочки (`confirmations`).
8. **BOM.** JSON от Блокнота и PowerShell начинается с BOM: читай через `profile::read_json`.
9. **Скрипты `.ps1` пиши только ASCII.** Windows PowerShell 5.1 читает файлы без BOM как ANSI, кириллица ломается.
10. **Длинный путь проекта** даёт `LNK1104` у линкера MSVC: собирай с `CARGO_TARGET_DIR` в коротком пути.
11. **Права администратора.** Без них `OpenProcess` для многих игр падает, это ожидаемо; сообщение об ошибке это объясняет.
12. **Живые значения в полях ввода** (число, ползунок, список) ставит `syncControls` в `cheat-list.js`, а не разметка. Иначе при каждом опросе поле пересоздаётся и ввод теряется. Поле, в котором стоит фокус, не трогать.
13. **Ключи в `data-*` атрибутах** не должны содержать управляющих символов: HTML-парсер заменяет U+0000, и ключ перестаёт совпадать. Так ломалось сворачивание закреплённых.
14. **Инъекция кода.**
    - Пещеру не освобождать: поток игры может выполняться внутри неё. Память живёт до конца процесса игры.
    - Параметр писать в пещеру до того, как ставится переход.
    - Перед патчем проверять `code_conflict`.
15. **Не убивай `fahrenhack.exe`, пока включён патч кода.** Восстановление кода идёт в `detach` при закрытии окна. После `Stop-Process` патч остаётся в игре, сигнатура перестаёт находиться (`missing`). Перед пересборкой выключай читы или вызывай `/api/detach`.
16. **Не прерывай `re-probe watch`.** Он снимает аппаратные точки останова только в конце. Если убить процесс на середине, регистры Dr0–Dr7 останутся на потоках игры, и при следующем обращении к адресу игра упадёт. Если всё же прервал, сразу запусти `watch` с тем же адресом на 1 секунду: в конце он очистит регистры всех потоков.

## Правила проекта (не нарушать)

- **Только одиночные игры.** Блок античитов (`ANTI_CHEAT` в `src/app/`) не ослаблять.
- Не обходить DRM, anti-tamper, проверки целостности и античит. Не менять файлы игры на диске.
- Никаких читов на DLC, микротранзакции и платный контент.
- Не копировать таблицы Cheat Engine, офсеты и код из чужих трейнеров. В папке RE4 у пользователя лежит сторонний трейнер: его не запускать и ничего из него не брать.
- Не добавлять в репозиторий файлы, логотипы и обложки игр. Обложки берутся из локального кэша Steam во время работы.
- Пульт по умолчанию выключен. Каждый запрос `/api` требует токен.
- Коммитить и пушить — только по просьбе владельца.
