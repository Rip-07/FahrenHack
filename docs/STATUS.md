## Resident Evil 4 (сборка 69a8f652-e405000)

Проверено на живой игре владельцем, в том числе **без модов** (у владельца стоит REFramework как `DINPUT8.dll`; повторная проверка без него прошла). Эти читы находятся сами, по сигнатурам кода, и переживают загрузку сохранения, смену локации и перезапуск игры:

| Чит | Где лежит | Как найдено |

Первая цепочка здоровья с `+0x4D4` была ошибкой: объект здоровья случайно лежал сразу за объектом персонажа. После смены локации заморозка писала 1188 в чужую память. Правильный путь идёт через указатель `+0x148`.

Песеты в RE4 не зашифрованы. Точный поиск не работал из-за трёх копий для интерфейса, которые обновляются с задержкой.

### База типов RE Engine

`re-probe` читает собственную базу типов игры (`TDB`, версия 71, в RE4 по `re4.exe+D691E00`) только чтением памяти. Раскладка найдена опытным путём:

| Что | Где | Запись |
|---|---|---|
| строки | `hdr+0xD0`, размер `hdr+0x50` | строки с нулём в конце |
| реализации типов | `hdr+0x68`, число `hdr+0x18` | 48 байт: имя `+0` (младшие 22 бита), пространство имён `+4`, размер данных `+8` |
| поля | `hdr+0x88`, число `hdr+0x1C` | 12 байт: флаги, смещение в данных, имя `+8` (младшие 22 бита). Смещение в объекте = смещение в данных + `0x10` |

| методы | `hdr+0x78` + 4, число `hdr+0x20` | 12 байт: флаги, имя `+4`, два u16 |
| записи типов | `hdr+0x60`, число `hdr+0x0C` | 72 байта: `+0x0C` биты 6.. — номер реализации, `+0x14` размер, `+0x40` таблица виртуальных методов объектов (первое поле любого объекта) |

Реализация: `+0x18` младшие 16 бит — число методов. Регистрация встроенных типов — записи по 0x28 байт в `re4.exe`: `+8` номер типа, `+0xC` размер, `+0x14` число методов, `+0x20` таблица функций. Функции в таблице идут в порядке методов класса, но иногда с лишней вставкой (виртуальные методы), поэтому нужную функцию лучше подтверждать по коду (`fuses`, `ftable`). Смещения полей из базы считаются от начала собственных полей класса: у наследников к ним прибавляется размер полей родителя.

Команды: `tdbobj <адрес>` (класс объекта и его полей-указателей), `tdbinst <часть имени класса>` (все живые объекты класса), `tdbfield <часть имени>`, `tdbimpl <тип>`, `tdbgrep <строка>`, `tdbmethods <метод>`, `tdbregall <тип>` (регистрация и таблица функций), `ftable`, `fuses`.
Инструмент исследования: `tools/re-probe` (точки останова «кто пишет/читает адрес», дизассемблер, поиск значений и указателей, подсчёт совпадений сигнатуры, база типов). Сборка: `cargo build --release --manifest-path tools\re-probe\Cargo.toml --target-dir target\re-probe`. RE4 переносит подключение отладчика без проблем, с модом и без.

Ещё не сделано:
- нож: прочность — поле предмета `_CurrentDurability` `+0x30`, нужен путь к живому объекту ножа;
- жетоны, маленькие ключи, CP (пока калибровка).

## Следующие шаги

0. **Расширенный набор читов RE4.** Список желаемого — у владельца. Движок и интерфейс для них готовы (этап 1). Что осталось:
   - **этап 2, данные через калибровку:** песеты, шпинели, золотые и серебряные жетоны, очки CP, время игры, маленькие ключи, стаки предметов. Перевести их в `number` или `slider`;
   - **этап 3, исследование кода на запущенной игре** (`inject`/`patch`): неуязвимость, броня, бесконечные предметы, крафт, бесплатный торговец, отдача, перезарядка, точность, скорострельность, урон, убийство с одного выстрела, скорость игры, FOV, полёт сквозь стены, ранг S+, режим «Наёмники». Для этого нужен инструмент «что записывает в этот адрес» и дизассемблер (например, крейт `iced-x86`). Защита RE4 может закрывать игру при отладке; обходить её нельзя (см. правила).
   - **не делаем:** редактор Exclusive Upgrade Tickets — они продаются за реальные деньги.
1. **Остальные читы RE4** тем же способом, что и в таблице выше: найти значение через `re-probe`, затем код и статическую переменную, и записать сигнатуру в профиль. Тип прочности ножа не известен: возможно, нужно `f32`.
2. **Доделать аудит окна.** Аудит начинался, но прервался вместе с предыдущей сессией. Что проверить:
   - **JS-среда WebView2:** `confirm()`, `navigator.clipboard` на `http://127.0.0.1`, автозапуск звука, Gamepad API;
   - **окно без рамки:** изменение размера за края, разворачивание и панель задач, двойной клик по шапке для разворачивания после `drag_window()`;
   - **ввод:** стандартные клавиши WebView2 (F5, Ctrl+R, F12, Ctrl+колесо, Alt+F4, кнопки мыши «назад» и «вперёд»), фокус при открытии окна; при фокусе в окне FahrenHack горячая клавиша срабатывает и через `GetAsyncKeyState`;
   - **жизненный цикл:** закрытие кнопкой и по Alt+F4 должно вызывать `on_exit` (восстановление патчей) и завершать процесс. Второй экземпляр: два потока горячих клавиш переключат чит дважды, нужна защита от второго запуска. Резервный путь без WebView2.
3. **Релиз 0.2.0** после проверки читов RE4: поднять версию в `Cargo.toml`, тег `v0.2.0` запускает CI-релиз.
4. **Перед публикацией** (см. LEGAL.md):
   - убедиться, что бренд FahrenTech принадлежит владельцу;
   - проверить название FahrenHack по базам товарных знаков;
   - вписать имя в `LICENSE`.

## Идеи

- Экранная цифровая клавиатура для ввода чисел с геймпада.
- Защита от запуска второго экземпляра: активировать уже открытое окно.
- Поиск указателей на больших играх: прогресс, отмена, ограничение памяти. Сейчас лимит — 120 млн пар указателей.
- Экспорт и импорт калибровки, чтобы делиться с другими игроками и пополнять `builds`.
